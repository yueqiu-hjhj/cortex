# Cortex vs Khoj — 深度比较（2026-10-23）

> 事实基线：Khoj 数据取自 GitHub API 与 docs.khoj.dev（2026-10-23 抓取，仓库最近推送 2026-08-02，版本 2.0.0-beta）；Cortex 取自本仓库代码与测试（624 lib 测试通过）。星标数会变，架构判断不会。

## 0. 一句话结论

**它们解决的不是同一个问题。** Khoj 是「**我的资料在哪都能问**」——触达最广的第二大脑；Cortex 是「**学完要记住、要产出**」——学习闭环 + 科研证据链。Khoj 赢在"入口"，Cortex 赢在"出口"。

---

## 1. 事实基线

| | Khoj | Cortex |
|---|---|---|
| 定位 | Your AI second brain | 本地学习 OS + 科研工作流 |
| 星标 / 许可 | 37.8k / **AGPL-3.0** | 私有自用项目 |
| 技术栈 | Python / Django / Postgres + pgvector | Rust / Tauri 2 / SQLite + sqlite-vec |
| 部署 | 自托管（Docker + Postgres）或官方云 | 单机单二进制，无账号、无云 |
| 客户端 | Web、桌面、Obsidian、Emacs、**WhatsApp**（5 端） | 桌面 + iOS 录音 + live sync（无手机聊天端） |
| 数据源 | 文件（pdf/md/org/txt）、**Notion**、**GitHub**、网页（Exa） | pdf/docx/pptx/epub/md/txt + 扫描件 OCR；**Zotero / Notion / GitHub Issues** 连接器；arXiv/PubMed 文献检索 |
| 模型 | 在线（GPT/Claude/Gemini）+ 本地（Ollama/LM Studio/LiteLLM/Vertex） | 多 provider + 本地；按槽位分配模型 |
| 最近活跃 | 2026-08-02 推送，2.0 仍是 beta | 当日仍在提交 |

---

## 2. 架构层

**Khoj**：一个 Django 单体 + Postgres/pgvector + 前端（Bun）。多用户、带账号、Web 优先，其他端是客户端壳。索引、检索、聊天、自动化都在服务端。**优势**：多端天然一致，多人可用；**代价**：自托管要维护 Postgres、认证、邮件服务（Resend），不是一个双击就能跑的东西。

**Cortex**：Tauri 桌面 + 单 SQLite 文件，检索（向量 + 关键词 + rerank + 摘要树）全在本机；iOS 端只做录音，靠 live sync 回传。**优势**：零运维、离线可用、数据就是一个文件；**代价**：没有服务端，所以"手机随时问"这件事天然缺失。

> 架构差异不是优劣，是取舍：Khoj 把复杂度放在服务端换取触达，Cortex 把复杂度收进本地换取简单。

## 3. 十个维度的深比

### 3.1 检索

| | Khoj | Cortex |
|---|---|---|
| 方式 | 语义 + 关键词（RAG） | 向量 + 关键词双路合并 + rerank + 摘要树上下文 |
| 范围 | 你的笔记/文档/Notion/GitHub | 你的资料 + 主题/科目结构 + 论文库 |
| 特色 | 自然语言找笔记，跨端一致 | 检索可解释（命中块、位置、分数），按科目/主题过滤 |

**判定**：Khoj 更"随手"，Cortex 更"可控"。单次找东西，Khoj 体验更顺；要找"这门课第三章的推导"，Cortex 的结构化过滤更强。

### 3.2 问答与引用

Khoj：RAG + 显示 reference notes，支持 `/notes`（只用笔记）、`/general`、`/online`、`/research`（深研）。引用是"用了哪些笔记"。

Cortex：回答带**冻结快照**的引用（citesnap），可重锚（源文本变了也能修），模型编造的引用会被丢弃并记录，答案健康度把"无引用/引用失效/被降级"分开统计，线程可滚动归档。

**判定**：Khoj 的引用是"来源列表"，Cortex 的引用是"可核验的证据"。写论文/复习场景，Cortex 领先一档；日常问答，Khoj 足够。

### 3.3 Agent

| | Khoj | Cortex |
|---|---|---|
| 定义 | 自托管文档里 = 一段 **personality 系统提示词**（Django admin 建） | 提示词 + 技能 + 工具白名单 + **权限分级** + 步数 + 运行审计 |
| 权限 | 无文档化的工具/权限分级 | read < write < network < **files**（文件读写，工作目录内） |
| 写操作 | 无提案机制 | **提案制**：`propose_note` 排队 → diff → 你点采纳才落库 |
| 多 agent | 各端共享会话？未见文档化 | **同一线程手动切换 agent，上下文保留** |
| 工具 | 斜杠命令（搜/图/代码/研究） | 17 个内置工具 + MCP 双向 + 文件工具 |

**判定**：Cortex 的 agent 平台明显更"工程化"；Khoj 的 agent 更接近"人格预设"。**这是 Cortex 少有的领先区**，但 Khoj 的 `/code`、`/diagram`、`/image` 这类"一条命令就出东西"的顺滑度更好。

### 3.4 自动化

Khoj：cron 式 automation，结果**发邮件**（自托管需配 Resend + 认证）。典型用法：每周简报、新闻摘要、事件提醒。

Cortex：cron 支持 `prompt`（跑一次 AI）、`sync`（拉连接器）、`planner`（生成当周计划并排期）；结果存为资料源或排进日历，**但没有外发通道**。

**判定**：Khoj 赢在"送达到你"；Cortex 赢在"改变系统状态"（排期、入库）。两者互补，Cortex 缺一条邮件/通知出口。

### 3.5 多端

Khoj 5 端（含 WhatsApp，个人数据需绑云账号）；Cortex 桌面 + iOS 录音。

**判定**：Khoj 完胜。Cortex 的 iOS 只解决"录进来"，不解决"问出去"。

### 3.6 学习闭环（Cortex 独占）

Khoj：无 SRS、无掌握度、无复习队列、无材料生成、无考试节奏。

Cortex：FSRS 排期 + BKT 掌握度 + 材料生成（速查表/测验/音频/幻灯片/信息图）+ 考试倒计时 + 英语训练 + 写作工具箱，且"生成的材料直接进复习队列，复习结果反哺掌握度"。

**判定**：9:0。这是两个产品最根本的分野：Khoj 帮你"找到"，Cortex 帮你"记住"。

### 3.7 科研工作流（Cortex 独占）

Khoj：问答 + 引用 + 深研模式，没有系统综述流程。

Cortex：PRISMA 8 维（每值带 verbatim 证据 + 摘录回链 + Excel 导出）、撤稿检查、期刊信号（DOAJ/core）、`.cortex-pkg` 归档、vault 静态加密。

**判定**：写综述/投稿，Cortex 是"能过审"的工具；Khoj 是"查资料"的工具。

### 3.8 隐私与部署

Khoj：可自托管，但自托管 = 维护 Postgres + 认证 + 邮件；官方云是默认路径。AGPL：**如果你分发修改版，必须开源**。

Cortex：数据就是一个 SQLite 文件；无账号、无遥测依赖；备份 age 加密 + `cortex-vault` 可整库加密。

**判定**：单机隐私 Cortex 更彻底；"多人/远程访问"Khoj 更成熟。

### 3.9 成熟度与生态

Khoj：37.8k 星、2.5k fork、172 open issues、文档完整、多语言、有云服务和付费计划。但**最近推送 2026-08-02，2.0 仍是 beta**——增长曲线可能放缓。

Cortex：单人项目，功能密度高、CI 严格（`-D warnings` + 624 测试），但边缘情况靠自己踩，没有社区。

**判定**：Khoj 领先，且短期内不会变。

### 3.10 成本

Khoj：自托管要一台常开的机器 + Postgres；云版按订阅。模型可本地，省 API 费。
Cortex：一台笔记本，模型按需（本地或 API），无订阅。

**判定**：持平；Cortex 的运维成本更低。

## 4. 场景决策表

| 你的需求 | 选谁 | 原因 |
|---|---|---|
| 在手机上/WhatsApp 随时问自己的资料 | **Khoj** | 5 端 + 云，Cortex 没有手机问答端 |
| 把 Notion / GitHub 接进来 | **持平** | 两家都有 Notion / GitHub 连接器；Cortex 多一个 Zotero |
| 学完要记住、要复习、要考试 | **Cortex** | FSRS + BKT + 材料生成，Khoj 完全没有 |
| 写系统综述、要证据链 | **Cortex** | PRISMA + 撤稿 + 期刊信号 |
| 每天/每周自动收到简报 | **Khoj** | 邮件送达；Cortex 的 cron 不外发 |
| 让 agent 读改我的代码/文件 | **Cortex** | files 权限 + 工作目录 + 提案制；Khoj 无文件工具 |
| 完全离线、零运维 | **Cortex** | 单二进制；Khoj 自托管要 Postgres |
| 多人/团队共用 | **Khoj** | 多用户 + 账号；Cortex 单用户 |

## 5. 威胁评估

**构成威胁的场景**：你的核心诉求从"学"转向"随手查"。一旦你习惯了在手机上问一句就得到答案，Cortex 的"打开电脑、选科目、检索"就显得重。Khoj 的 WhatsApp/浏览器入口是真实的产品优势，不是噱头。

**不构成威胁的场景**：复习、考试、写论文、做材料。这些 Khoj 没有数据模型（没有掌握度、没有排期、没有证据链），不是"做得差"，是"不在它的产品里"。

**一个反向观察**：Khoj 的 agent 很薄（提示词级），Cortex 的 agent 很厚（工具/权限/提案/审计）。如果 Khoj 未来把 agent 做厚，它会同时拥有"入口"和"执行"，那才是真正的威胁；目前它只有入口。

## 6. 值得借鉴的（按性价比）

1. **给 cron 加一条外发通道**（邮件/系统通知）。Cortex 已经能生成内容，只差"送到你眼前"。成本：半天；收益：每日简报/周报闭环。
2. **斜杠命令式的轻量动作**。Khoj 的 `/image`、`/diagram`、`/code`、`/research` 是「想到就得到」；Cortex 的材料生成更重、入口更深，聊天里可以加一层轻指令，把重流程留在一键生成。
3. **只读 Web/PWA 视图**（"今天/问一句"）。不需要 5 个客户端，一个局域网只读页就能覆盖 80% 的手机场景；Cortex 已有 live sync 与 HTTP 服务基础。
4. **一条命令出图/出图表的顺滑度**。Khoj 的 `/image`、`/diagram` 是"想到就得到"；Cortex 的材料生成更重但入口更深。可以在聊天里加轻量指令。

## 7. 不该借鉴的

- **Django + Postgres 技术栈**：Cortex 的单文件 SQLite 是核心优势，换栈等于放弃"零运维"。
- **5 个原生客户端**：维护成本远大于收益；只读 Web 页足够覆盖。
- **agent = 系统提示词**：Cortex 已经领先，不要回退。
- **云优先 + 账号体系**：与自用定位冲突。
- **直接抄代码**：Khoj 是 AGPL-3.0，分发修改版会触发开源义务；借鉴产品思路可以，复制实现不行。

---

## 8. 结论

Khoj 是更好的**第二大脑**，Cortex 是更好的**学习与研究工作台**。

- 如果你的日常是"查—读—问"，Khoj 的触达和成熟度值得直接用；
- 如果你的日常是"学—练—考—写"，Cortex 的闭环是 Khoj 给不了的；
- 两者可以并存：Khoj 当入口（手机随手问），Cortex 当工作台（桌面深度学）。

**真正该警惕的不是 Khoj 现在比你强的地方，而是它把"入口"做成习惯之后，你会懒得打开工作台。** 对抗这件事的办法不是加客户端，而是让工作台的"每日一屏"足够值钱——这也是为什么"长期计划 → 周 → 日"和"每日复盘"比多端更重要。
